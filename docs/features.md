# 機能一覧

[README](../README.md) の特徴ダイジェストの全文版。各機能の挙動の細部・制限・実測値を記載する。

## 検索

- **ripgrep による高速検索** — 正規表現・大文字小文字区別・単語単位・glob フィルタに対応
- **リアルタイムストリーミング** — 検索結果を SSE で逐次表示
- **複数検索タブ** — 最大 10 件の検索を並行保持。タブを切り替えて結果を比較できる
- **検索結果の絞り込み** — AND（スペース区切り）/ OR（`|`）/ 除外（`-word`）に加え、`file:foo` / `path:foo` でファイル名・パス単位に絞り込み
- **関数セパレータ** — C 系ファイルの検索結果を所属関数ごとに `ƒ 関数名` の行で区切って表示（「30 ヒットだが実は 2 関数」が一目で分かる）。セパレータをクリックで関数定義へジャンプ。`ƒ` ボタンで ON/OFF
- **0件の理由ヒント** — glob が 1 ファイルにもマッチしていない / 正規表現構文を literal 検索した、などの「検索条件ミス」を 0 件時に結果パネルへ表示
- **索引ファイルの自動除外** — `tags` / `GTAGS` 等の索引ファイルは検索対象から自動で外れる（明示的に glob 指定すれば検索可能）
- **種別バッジ** — 検索ヒット行が関数定義・構造体・`#define`・enum・typedef のどれかを自動判定してバッジ表示
- **検索ディレクトリ指定** — サブディレクトリのみを対象に絞れる。glob パターンの入力履歴付き
- **シンボル検索パネル** — 左のアクティビティバー（ƒ）から、関数・構造体・マクロを名前のライブサーチで探す。種別チップで「関数だけ」「マクロだけ」に絞り込み、スペース区切りのうろ覚え AND（`recipe save` → `recipe_save`）と 場所（`dir/` / `-test`）と含めるファイル（`*.c,*.h`）の絞り込み欄に対応。ctags 索引が必要（Alt+Shift+T のキーボード版と同じバックエンド）
- **検索履歴** — Alt+H で過去の検索クエリ一覧を表示
- **検索スタック・履歴の hover** — 各エントリにマウスを乗せると、その検索を保存したときの条件（ルート / glob / フラグ / エンコーディング）が tooltip で見える。現在の検索フォームと条件が違うエントリには金色の `＊` マーカー
- **文字コード自動判定** — UTF-8 / UTF-16 / Shift-JIS / EUC-JP を自動検出して表示。非UTF-8 で復号されたファイル行の「非UTF-8」バッジをクリックすると、検索エンコーディングを SJIS → EUC-JP → UTF-16 で循環させて即再検索できる

## エディタ

- **Monaco エディタ** — VSCode と同じエディタで該当行にジャンプ
- **複数タブ** — 開いたファイルはタブで切り替え可能
- **定義ジャンプ** — Ctrl+クリック / F12 でシンボル定義へジャンプ。GNU Global が利用可能な場合は構文解析済みインデックスを優先し、ripgrep にフォールバック。複数候補はピックリストで選択
- **ホバープレビュー** — シンボルにマウスを乗せると定義スニペットとその直前コメント（`//` / `/* */` 両形式）をポップアップ表示。GNU Global 対応。`#define FOO BAR` のような別名マクロは参照先を、`(2|ERR_R_FATAL)` のような式は式中の各マクロを、最大4枚のカードで展開する。`(2|ERR_R_FATAL)` のような定数式マクロは計算値（`= 66 (0x42)`）をヘッダに表示。数値・文字リテラル（`0x42` / `192` / `'A'`）へのホバーは 10進/16進/2進と立っているビット位置を即時表示。右クリックの「基数変換電卓」では `1<<6 | 2` のような式や `(1<<4)==16` の検算に加え、`ERR_R_MALLOC_FAILURE == 65` のようにマクロ名や enum メンバ名を含む式も索引で値を解決して計算できる
- **F3 / Shift+F3** — 検索ヒット行を順番にジャンプ
- **行メモ・範囲メモ** — 任意の行または選択範囲にメモを付けてエディタ上にインライン表示（Alt+M で表示切り替え）。「一覧」ボタンでメモリストパネルを表示し、グループ・カラーラベルで整理、クリックでジャンプ、一覧から編集・削除。**メモ付きグラフノードもこの一覧に統合表示**（◎ アイコン、読み取り専用 + ジャンプ）
- **外部エディタとの同期** — 外部エディタでファイルを変更すると Monaco エディタが自動で内容を更新。バックグラウンドタブ時は更新を停止
- **追跡ハイライト** — Alt+H または右クリックでカーソル位置の単語を色付きハイライト。複数単語を最大 8 色で同時管理。**別ファイルを開いても同じ単語がハイライトされ続ける**
  - カーソルワード → 単語単位マッチ / テキスト選択 → 部分マッチ（チップに「単語一致」「部分一致」を表示）
  - タブバー直下のチップ一覧で「‹ 前へ / 次へ ›」ジャンプ、単語クリックでピン箇所に戻る、× で解除
- **#ifdef 可視化** — C/C++ の条件コンパイルで無効になるブロックをグレーアウト。ヘッダの `#if` ボタンから条件をリストで管理し、真偽の反転・追加のたびに即適用。開いているファイルの `#if` が実際に見ている名前を候補として提示し、ファイルを移っても条件は効き続ける
- **C/C++ セマンティックハイライト** — `editor-c.js` による追加色付け（詳細は後述）
- **ナビゲーション履歴** — Alt+← / Alt+→ で閲覧履歴を前後に移動
- **Ctrl+P ファイルクイックオープン** — fzf スタイルのファジー検索（スペース区切りで AND 絞り込み）
- **Alt+Shift+T シンボルクイックオープン** — 関数・マクロ・typedef を名前のうろ覚えでジャンプ（`recipe save` → `recipe_save` の定義へ）。Ctrl+P 内で `#` 始まりでも起動。ctags 索引が必要
- **スクロールバーマーカー** — グラフ pin・関数実態・呼び出し箇所（teal）と行メモ（カテゴリ色）をスクロールバー上に表示。長いファイルでも調査痕跡の分布が一目で分かる
- **デバッグ行の挿入** — カーソル行に printf 等のデバッグ行をテンプレ or 自由入力で挿入し、grepnavi が場所を記録。一覧からジャンプ・書き換え・個別/一括撤去でき、消し忘れは残数バッジで防ぐ。グループ名を付けて撒き分ければ（例: `path-A`）グループ単位でまとめて撤去でき、テンプレの `{group}` で実行出力からも識別できる。挿入行だけをファイルのエンコーディングに変換して書き込むため SJIS/EUC-JP のソースも壊さない（UTF-16 は非対応）。既存行の変更・削除は一切しない。入力欄は本体と同じ Monaco で、字下げガイド・C の色付け・挿入先ファイルのタブ設定が効く。**変数名・構造体メンバーの補完**が使え（`.` や `->` の後はその構造体のメンバー、それ以外は挿入先の行から見えるローカル変数・引数・グローバル・マクロ。ポインタに `.` と打つと確定時に `->` へ直る）、書いている内容は**挿入先の行の直後に薄字でプレビュー**されるので、字下げと前後関係を書きながら確かめられる。補完は ctags 索引を使う（[`/api/complete`](api.md)）。ショートカットは Alt+P、デバッグ行の上では右クリックから書き換え・撤去、`Delete` キーで即撤去、`Tab` / `Shift+Tab` で字下げができる。位置を直したいときは右クリックの「デバッグ行を移動」で移動モードに入り、移動先の行をクリックする（ID を保つので、本文に焼き込まれた `{tag}` と実行時の出力が食い違わない。別ファイルへも移せる）。一覧の ⇅ からはカーソル行へ移せる。個別の撤去と移動は 30 秒以内なら `Ctrl+Z` で元へ戻せる。外部エディタで手動削除・変更した行の記録は、撤去が照合で止まったときに「記録だけ削除」で片付けられる（ファイルには触らない）。

## 調査グラフ（ツリー）

- **ノード追加** — 検索結果の `+` ボタン、またはエディタのテキスト選択 → Alt+Shift+G でノードを追加
- **ラベル・メモ** — ノードごとにラベル（表示名）とメモを編集（F2 / 右クリックメニューから）
- **メモを関数実態にも自動表示** — 呼び出し箇所のノードに付けたメモは、その関数の実装行にも同期して表示される（中空 teal 円のグリフ + ホバーで本文）。「呼び出し ↔ 実態」が視覚的にリンクされ、別ファイルを開いた瞬間に「ここは調査中の関数だ」と分かる
- **逆方向の同期（実態 → 呼び出し箇所）** — 関数の定義行そのものを pin すると、開いているファイル内のその関数の呼び出し行が破線 + 中空三角グリフで強調される。ホバーでメモ表示、グリフクリックで実態へジャンプ。関数名でのホバーは別ファイルでもメモが出る
- **ツリー表示とグラフ表示の切り替え** — ボタンで D3.js のフォースグラフに切り替え可能
- **複数ツリー** — 1 プロジェクトに複数の調査ツリーを作成・タブで切り替え
- **ツリーメモのインライン表示** — Alt+Shift+N（またはボタン）でノードのメモをツリー上にコメント風に常時表示
- **ノード展開** — ノードのシンボルを検索してヒットを子として追加（右クリック「展開」）
- **ホバープレビュー** — ノードにマウスを乗せると関連コードのポップアップを表示
- **カラーバッジ** — ノードに色付きラベルを付けて分類・マーキング（右クリック「バッジ」から編集）

## ノード操作

- **ドラッグ&ドロップ** — ノードを別ノードにドロップして親子関係を変更。drop-before / drop-after のライン表示で挿入位置を確認
- **⠿ ハンドル** — ノード行の左端ハンドルを左右にドラッグしてインデントレベル（階層）を変更
- **キーボードでの移動** — Shift+Alt+Arrow キーで選択ノードを移動（↑↓ で兄弟間、← でレベルアップ、→ でレベルダウン）
- **↑ / ↓ で選択変更** — ツリービュー上でフォーカス外（テキスト入力・エディタ以外）のとき、Up/Down 矢印キーで選択ノードを切り替え

## C/C++ セマンティックハイライト

`static/js/editor-c.js` が C/C++ ファイルに対して以下の追加ハイライトを適用します。Monaco の組み込みシンタックスハイライトとは別レイヤーで動作します。

| 種類 | 色 | 抽出ロジック |
|------|-----|-------------|
| static 変数 | `#9cdcfe`（水色）+ italic | ファイル内の `static [型] 変数名` 宣言を正規表現で検出し、同名の全出現箇所に適用。`->` `.` の後（メンバーアクセス）は除外 |
| 関数呼び出し | `#dcdcaa`（黄） | `識別子(` パターンを正規表現で検出（`if` `while` `sizeof` 等のキーワードは除外）|
| 定数・マクロ | `#e5c07b`（黄） | ctags インデックスから取得した `#define` マクロ・`enum` 値名を検出（ctags インデックス未生成時は非表示） |

**注意事項（ヒューリスティックの限界）**

- **static 変数**: `->` / `.` を使ったポインタ・構造体メンバーアクセスは除外しますが、複数変数を1行に宣言する `char *a, *b;` の場合、2番目以降の変数は検出されないことがあります
- **関数呼び出し**: 実際に関数かどうかの意味的判断はせず、`識別子(` 形式をすべてハイライトします。関数ポインタ変数の参照なども含まれます
- **定数・マクロ**: ctags インデックスに登録されたシンボルのみ対象。ただし誤検知抑制のため大文字を含まない識別子（`likely` 等）は除外されます

static 変数・関数呼び出しはテキストパターンに基づくヒューリスティックです。定数・マクロのみ ctags による意味解析を使用します。

## アドオン

アドオンは `static/addons/<name>/addon.js` + `addon.css` で実装されており、`static/addons/addons.js` の `ADDONS` 配列に名前を列挙するだけで有効化できます。

### コールツリー

関数の呼び出し元（callers）/ 呼び出し先（callees）をツリー形式で表示します。

- エディタ上の関数名を選択して右クリック or ツールバーの「Call Tree」ボタンで起動
- 入力欄に関数名を入力して実行（Enter または Go）
- `callers` / `callees` タブで方向を切り替え（タブを戻っても展開状態を保持）
- ノードをクリックして実装箇所へジャンプ（プロトタイプ宣言ではなく定義本体を優先）。`▶` で再帰的に展開
- Esc で検索欄をクリア（もう一度 Esc でパネルを閉じる）
- GNU Global が利用可能な場合、Callers は `global -xr` による構文解析ベースの参照検索を使用（ripgrep より誤検知が少ない）。検索のたびに、実際に使ったエンジンと所要時間をパネルに表示し、ホバーで内訳（索引の呼び出し / ファイル解決 / rg 走査・読んだファイル数・サーバのビルド版）が見える——遅い環境で「どこが遅いか」をその場で切り分けるための計測
- 関数ポインタのテーブルで登録される関数（メソッドテーブル・ops 構造体）は、登録行が「ファイル名:行」のノードで出ます。囲む関数が無い参照も落としません。登録箇所こそが「誰が呼ぶのか」への答えなので、索引の結果をそのまま返します（実測: openssl の `ssl3_read_bytes` で 1.85 秒 → 0.05 秒）

### ジャンプマップ

定義ジャンプの履歴をグラフとして可視化します。どのシンボルからどのシンボルへジャンプしたかを追跡し、コード読解の経路をノード・エッジで表示します。

- エディタのツールバー「Jump Map」ボタンまたは右クリックメニューから起動
- ファイル単位にシンボルをグループ化するフォルダビューに切り替え可能
- シンボルの種別（関数・構造体・enum・define 等）をノードの色で区別
- ミニマップでグラフ全体を俯瞰しながらナビゲーション
- draw.io 形式でエクスポート可能

### C インクルード依存グラフ

`#include` の依存関係を D3.js フォースグラフで可視化します。

- エディタで C/C++ ファイルを開くと起点ファイルが自動セット
- ツールバーの「Include Graph」ボタンでパネルを開き「Analyze」で解析開始
- ノードをクリックして上流・下流を展開。Ctrl+クリック or ダブルクリックでエディタに表示
- 「Collapse All」でグラフを折りたたみ

### 参照マップ

GNU Global の索引から「どのまとまりが、どのまとまりの実装を参照しているか」を集計して表示します。ジャンプマップが訪問の足跡なのに対し、こちらは**一度も開いていないツリーでも全域が最初から見える**のが違いです。

- 初回はパネルに生成ボタンが出ます（読む量と見込み時間を表示してから、押されたときだけ生成）。生成中は進捗が流れます
- 結果はツリー直下の `.grepnavi-refmap` に保存され、次回からは読み込むだけ（実測: Linux カーネルで初回 87 秒、以後は保存した地図を読むだけで 1 秒未満、ファイルは 20 MB）
- 全体図は被参照の多い順。大きいまとまりは重さで分割され、`drivers/net` のような深い境界が `net` と同列に並びます。分割された親の行は「残り」と表示され、子の合計にはなりません
- まとまりをクリックすると「外から / 内部 / 外へ」の3タブ。件数を常に出すので、開いていない面も見落としになりません。外から / 内部 は行き先ごとに束ねて表示します（見出しは「X を使っている N か所」で、その下に使っている側が並ぶ。▾ で畳めます）。外へ は逆向きの1見出し「X が使っている N か所」の下に、呼んだり読み書きしたりしている外の実装が並びます
- 見た場所は履歴に残り、パネル左上の ←/→ か `Alt+←` / `Alt+→` で行き来できます（パネル内にフォーカスがあるときだけ。エディタ側の履歴とはキーを共有しつつ干渉しません）
- パンくずの各段の `▾` で、その直下のまとまりを一覧（全体図は被参照の多い順に絞られるため、そこに出ないディレクトリへはここから移動します）。祖先の段からは兄弟へ、末尾の段からは今いるまとまりの中へ。ファイルツリーのフォルダ右クリック「参照マップで見る」からも直接開けます
- 絞り込みは3タブ横断（スペース区切りは AND、`-` で除外）。パスだけでなく行に付いたシンボル名にも当たるので、関数名で「その関数が絡む行だけ」に絞れます（チップは見本 8 件で、切れている行は `…` をクリックすると残りを全部開けます。開いた行は絞り込みも全シンボルに当たり、まだ開いていない行については取りこぼしうる件数を添えます）。シンボルのチップはクリックで定義へ、Alt+クリックでその参照行を一覧
- 数えるのは「(シンボル, 参照元ファイル)」の組で、出現行数ではありません。同名の実装が複数あって索引だけでは指す先を決められないシンボルは**推測せずに除外し、その件数を応答に含めます**
- 索引は名前だけで突き合わせるため、そのままでは偽の関連が混じります。`static` 定義への他ファイルからの参照（C の規則上ありえない。他ファイルのローカル変数 `cnt` などが一致してしまう）と、ヘッダに現れた名前（プロトタイプ宣言は実装の利用ではない）は数えません。除外した件数はフッターに出ます（実測: openssl-1.1.1q でファイル対のエッジ 7,437 → 6,173）
- 「対象から外すもの」の宣言はここにも効きます

### 状態遷移図

状態変数（`s->early_data_state` など）への代入を集めて、遷移図と一覧を出します。エディタで変数名にカーソルを置き、Alt+A の「この語に何が入るか」から開きます。

- `enum` の全メンバー、または共通接頭辞の `#define` 群を状態の全体集合として拾い、**一度も代入されない状態**（消し忘れ・初期値専用・関数ポインタ経由でしか設定されない状態）を孤立ノードとして残します
- 追えなかった代入は `?` ノードからの破線、定数でない代入は式のまま表示します。**実線の辺だけがコードに根拠のある遷移**です
- 状態が多い図は潰れるため、一覧から1つ選んでその隣接だけを描く表示に切り替えられます
- 遷移を選ぶとその代入行へジャンプします

## プロジェクト

- **プロジェクト保存** — グラフ・メモ・ルートディレクトリを JSON ファイルに保存（Ctrl+S）
- **名前を付けて保存 / 開く** — 複数のプロジェクトファイルを切り替えて使用可能。開いたファイルは自動でそのルートに登録される
- **プロジェクトマネージャー** — 左のアクティビティバーからプロジェクト一覧を表示。ルートと JSON の組み合わせを名前付きで登録し、ワンクリックで切り替え。ルートごとに複数の JSON を管理でき、ツールバーのドロップダウンからも即切り替え可能
- **.grepnavi ファイル** — ルートディレクトリに自動生成される設定ファイル。そのルートに紐づく JSON ファイルのリストと、対象から外すパスを保持。複数ポートで起動した場合も同じ `.grepnavi` を共有する
- **外部エディタ設定** — プロジェクトメニューの「設定…」から VS Code またはカスタムエディタ（最大 3 件、名前とコマンドで定義）を設定・切り替え。`{file}` / `{line}` プレースホルダーを使ったコマンドを指定するため、Vim・Emacs 等任意のエディタに対応
- **対象から外すもの** — 「設定…」で、このプロジェクトが読まないパスを宣言（`.grepnavi` に保存）。**書き方は `.gitignore` と同じ**で、`!` の打ち消しや `#` のコメントも使える。検索の絞り込みではなくツリーの宣言なので、検索・参照・定義ジャンプ・ファイル一覧・MCP のすべてに効き、検索の glob や「除外ファイルも検索」（Alt+I）では戻らない。tarball を展開して doxygen をかけたツリーでは生成物が同居する（実測: openssl-1.1.1q で `ssl3_read_bytes` を検索すると 188 件中 79 件が `html/` 配下の生成 HTML だった）。**既定は空** — 何が生成物かはツリーごとの事情なので、grepnavi の側から推測して外すことはしない
